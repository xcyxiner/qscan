# QScan 演示原型需求文档

日期：2026-05-23

## 背景

当前项目方向见 docs/README.md，核心技术栈为 Qt + C++ + VTK/OpenGL + 多线程 + 串口/网络通信，目标能力覆盖设备通信、数据处理、图像可视化与 UI 交互。

本轮需求不追求真实安检设备联调，而是先做出一个适合技术验证和作品集展示的桌面原型，重点证明系统能够跑通一条完整的数据链路。

## 目标

构建一个可演示的安检扫描桌面原型，使观察者能够在短时间内理解系统具备以下能力：

- 能接入模拟设备并持续接收扫描数据
- 能对输入数据做基础图像处理
- 能在界面中实时显示扫描图像
- 能通过简单交互看到参数调整带来的结果变化
- 能展示系统运行状态与处理过程记录

## 目标用户

本阶段的主要受众不是终端安检人员，而是技术面试官、评审老师或项目观察者。

他们关心的不是行业流程完整度，而是：

- 项目是否具备完整系统思维
- 是否能体现 Qt/C++ 桌面工程能力
- 是否体现出数据流、处理链路和界面响应之间的配合

## 核心演示瞬间

第一优先级的演示瞬间是：界面实时显示扫描图像。

这意味着最小版本必须优先保证“数据进来”到“画面出来”的主链路稳定成立，再叠加少量能增强说服力的控制和状态信息。

## 第一阶段范围

第一阶段包含以下 5 个能力块：

1. 模拟设备连接
   - 提供一个模拟数据源，模拟设备持续输出扫描数据
   - 界面可看到连接状态和启动结果
2. 实时图像显示
   - 将输入数据转换为可观察的扫描图像
   - 支持连续刷新，形成实时显示效果
3. 基础图像增强
   - 提供至少一组基础图像处理能力，例如亮度、对比度或简单增强
   - 调整后应能在界面中直观看到结果变化
4. 参数调节面板
   - 用户可以通过简单控件修改关键显示或处理参数
   - 交互反馈应及时，不应明显阻塞主界面
5. 日志与状态面板
   - 显示连接状态、数据接收状态和关键运行日志
   - 用于补强系统完整性和工程可信度

## 非目标

以下内容不进入第一阶段：

- 真实安检设备或真实协议联调
- 高复杂度图像识别算法
- 完整 3D 体绘制或复杂三维工作流
- 高保真行业业务流程还原
- 多端协同、账号体系或远程部署能力

## 成功标准

第一阶段完成后，应至少满足以下结果：

- 演示时可以稳定启动并展示完整链路
- 观察者能在 1 分钟内看懂数据从输入到显示的过程
- 调节关键参数后，图像变化是可见且即时的
- 界面在持续刷新数据时仍保持基本可操作
- 项目展示出来的是“完整系统原型”，而不是孤立的图像小工具

## 风险与取舍

- 如果同时追求通信、渲染、3D 和复杂算法，第一阶段很容易失焦
- 如果只做单点图像显示，又会削弱“完整链路”的作品价值

因此本阶段的取舍原则是：优先保证主链路闭环，其次补足少量能增强可信度和展示效果的控制与状态能力。

## 后续扩展方向

当第一阶段稳定后，可按以下顺序择机扩展：

1. 增加处理前后对比视图，提升演示说服力
2. 引入更丰富的伪彩或可视化表现
3. 补充 VTK/OpenGL 的更强渲染能力
4. 替换模拟输入为更接近真实设备的数据源
5. 逐步增强模块边界，为后续工程化做准备
